SECTION E — HIGH-END 3D-STYLE EIGHT-SPOKE WHEEL
============================================================
Create a CUSTOM eight-spoke ship-steering-wheel-inspired fashion selector. NOT a stock image and NOT a literal rustic wooden pirate wheel. Stylize it for HELLO! streetwear.

GEOMETRY & MATERIALS
- Exactly 8 evenly spaced spokes, separated by 45 degrees, with 8 visibly round ball/grip handles at the ends.
- Outer ring, beveled metal edges, center hub, light-catching rim, depth/shading, gentle metallic highlights, realistic cast shadow, restrained ambient occlusion.
- A physically plausible 3D LOOK is required. Approaches: lightweight Three.js/WebGL if already available and sensible, or carefully layered SVG/CSS perspective with gradients, shadow and specular highlights. Prefer a well-rendered, fast 3D LOOK to a heavy broken 3D engine.
- Wheel must be drawn from actual components/geometry, NOT baked into a decorative hero background; points must be separately interactive.
- Rotate as an integrated body (outer ring + spokes + handles + hub) with believable depth and motion.
- Use subtle wheel rotation inertia, snap-to-detent ease, and tactile selection feedback, but no uncontrolled spinning.
- A small directional highlight may move with the wheel; avoid flashing red glows, particle explosions or casino-style effects.

IDLE AUTOROTATION
- On desktop, rotate very slowly and continuously while user is idle. Approximately one revolution per 20–35 seconds or a similarly calm premium pace, configurable.
- Idle motion NEVER automatically switches model looks.
- Pause idle rotation on hover, pointer down, touch, focus-within, or manual interaction. Never fight the user's drag.
- After inactivity, optionally ease back into idle rotation WITHOUT changing selected outfit.
- Pause/stop if document is hidden, if reduced-motion is enabled, or if intersection-observed wheel leaves viewport.

POINTER / TOUCH / KEYBOARD INPUT
- Mouse drag: wheel rotates naturally with angular delta around wheel center; release invokes gentle inertia and snaps to the nearest 45-degree spoke position.
- Touch drag: same behavior, careful touch-action handling, prevent scroll only during a confirmed active wheel gesture. Still allow normal scroll outside the control.
- Balls: all eight endpoint balls remain individually selectable with clear hover/focus/selected states and sufficiently large hit areas. Clicking ball N selects look N, regardless of where wheel is currently rotated.
- Manual wheel turning: when user rotates wheel across a detent and releases/snaps, update selected look to that spoke's look; don't require only ball clicks. Outfit transition triggers ONCE per settled manual selection rather than on every animation frame.
- Buttons/keys: arrow keys step through looks (or rotate wheel), Enter/Space select focused ball, wheel container announces role and active look to screen readers.
- Avoid pointer vs click conflicts; dragging should not accidentally activate a ball.
- Respect keyboard focus, tab order and input accessibility; mouse wheel scrolling should not trap normal page scrolling.

STATE MODEL AND MATH
- Represent look selection separately from decorative idle angle; idle angle cannot inadvertently update selected look.
- Suggested state: selectedLookIndex (0..7), wheelRotationDeg (visual angle), isDragging, dragStartAngle, manualBaseAngle, isIdleRotating.
- Eight spokes = 45° each. Use atan2(pointer.y-centerY, pointer.x-centerX) to calculate drag angle. Normalize negative/over-360 rotations, handle wrap-around cleanly, snap on release, and derive selected index deterministically.
- If a user clicks ball N while the wheel is moving, stop idle rotation, rotate gently to bring N to the top/selection marker if helpful, then select outfit N. Make final state consistent.
- Provide UI feedback: look number 01–08, look title, highlighted selected ball or selected spoke, maybe a very subtle click sound ONLY if explicitly opted in (default muted).
